# 科研模型框架图

把模型实现转成读者能够沿箭头理解的科研框架图。让读者能回答：输入是什么、原模型有哪些路径、新模块接在哪里、特征怎样变换、结果如何融合。

本 skill 的默认风格来自用户认可的 BDC-CLIP 框架图：白底、浅蓝／浅黄原有模块、珊瑚色新增模块、细箭头、虚线分区、Token 小方块和矩阵网格。外层解释用中文，模块内部算法操作用英文。用户当次要求优先于这些默认偏好。

## 先选择工作方式

- **已有 SVG 或绘图脚本，只需改文字／布局**：直接修改可编辑源文件并重新导出，保持布局稳定。
- **从论文、代码或草图新建结构图**：先核对计算图，再用确定性绘图工具绘制 SVG；无需先生成一张位图。
- **用户要求展示 Token、Patch 切块、矩阵或张量变化**：阅读 [张量与表示可视化](references/tensor-visuals.md)，在指定接口或局部展开中实际绘制方块组合、矩阵网格或张量叠片，并标注前后形状与变换操作。不能只增加尺寸文字而仍以模块框代替所要求的表示变化。
- **用户明确要求 GPT Image 或需要探索画风**：使用环境中可用的图像生成 skill，遵守指定模型及其调用方式。生成稿用于确定构图和色彩；涉及精确公式、连线或后续编辑时，转入矢量重绘。
- **已有生成图出现乱码、错误走线或涂抹残留**：优先把它作为风格参考，重建可编辑图元；不能把 PNG 包进 SVG 就称作完成矢量转换。

新建／重绘时阅读 [视觉与语言规范](references/visual-style.md)；涉及模型结构或连线时阅读 [模型结构核对](references/model-checks.md) 中对应模型的部分。导出、字体、布局或修复任务阅读 [矢量制作与验收](references/vector-workflow.md)。只有处理 BDC-CLIP 时才阅读 [BDC-CLIP 案例](references/bdc-case.md)，其中事实只作为线索，须以当前代码复核。

## 从证据建立计算关系

1. 明确交付图描述的对象：论文原模型、当前实现、某次实验配置，或仅展示新增模块位置的概览。缺省按当前任务涉及的实现绘制。没有代码且只给模型名称时，声明采用的标准版本；有实质差异又无法判断时再询问，不把熟悉的变体默认为用户的实现。
2. 检查相关 `__init__`、`forward()`、模块开关、损失与推理融合；若涉及基线对比，再读原论文和原始实现。图注省略的模块不等于模型没有该模块。
3. 列出精简的节点／边清单：输入张量、模块操作、输出形态、消费者、训练／评估启用条件、证据位置。小修改只核查相关节点，不必全面审计仓库。
4. 区分原有设计、借鉴模块、适配改动和新增组合方式。来源论文支持某个机制，不自动证明当前完整组合的原创性或效果。
5. 再进行布局。参考图提供的是视觉风格，不能覆盖代码事实。先确定总图的表达粒度，已展开子层中的残差、归一化和输入来源不能随意省略；省略 Dropout 等细节时在图注说明。

### 结构准确性的关键区别

- **特征复用 ≠ 编码器共享参数**：独立视觉／文本编码器分别画出；同一输出供多条路径消费，可用分叉或对应端口表达。
- **并联补充 ≠ 串联处理**：从编码器特征直接读取输入的新模块应画成并联支路，在真实的残差相加处汇合，不能画成读取已有 logits。
- **双输入对齐 ≠ 表示依次转换**：视频和文本分别进入相似度节点，不能画成视频表示变成文本表示。
- **同一中间张量 ≠ 两套模块**：共享 Video BDC 等表示时用同一来源标记或明确分叉；若重复画以便阅读，要注明复用。
- **模块内部步骤 ≠ 模块输出后的新运算**：协方差、卷积压缩、分类头等应放在所属模块边界内，或另开局部放大图。
- **默认配置 ≠ 永久限制**：训练期启用、下游关闭等说明须核对实际开关；图注写清所示设置，不能据一次实验推断模块永远不可用于推理。
- 跨组交叉协方差一般不必对称；不要把所有网格都强制画成对称矩阵。

## 构图与语言

按拓扑选择布局：并联融合用从左到右的分支泳道，Encoder–Decoder 用方向一致的并排堆叠，主干加辅助模块用主路径配侧支路。具体选择见视觉规范。保持原有路径可识别，新增模块高亮，必要时用局部展开解释关键表示变化；没有新增模块时按角色配色，不制造“创新模块”。

外层标题、路径用途、输入来源、阶段说明、图例与图注用中文；模块内算法操作、方法名、标准缩写用英文。示例：外层“视觉分类 + SMCD”，内部 `Projection + Channel Groups`、`Cross-Group Covariance`、`Temporal Mean`。维度用真实数学符号，并在全图统一定义。

图标应表示张量形态而非装饰：Token 序列、帧 × Token 阵列、相似度矩阵、二阶表示、类别 logits。只画能帮助理解关键变换的图标；不要逐行图解代码。

## 交付与复用

- 默认交付可编辑 SVG、高清 PNG、矢量 PDF，保留可复现绘图源文件；已有项目渲染脚本能完成任务时优先复用。
- 文字保留为 SVG 文本对象。字符缺失时选支持中英文与数学符号的字体，重新排版并导出；不通过反复白底涂抹遮盖结构性错误。
- 至少检查一次完整预览，以及用户指出区域、文字密集区和融合节点的局部放大图。检查边界、连线、字形和结构，不以“渲染成功”代替图形验收。
- 结构、排版、格式分别验收；从输入沿每条边追到输出，核对残差起止点、融合输入和重复层边界。结构未核实不能用文本对象数量或无裁切来宣称模型正确。
- 验证 SVG 中模块、连线和标签可编辑，位图仅用于明确需要的输入图片／Patch 等素材，文件来自同一版源文件。扫描符号一致性，例如帧数 `F` 与文本端口 `T`，不能只改图例而漏改维度和输入端。
- 汇报成品路径、修正了什么，以及影响使用的真实限制。只知道指定了某个生成模型时，不能宣称已验证服务实际返回模型身份。
