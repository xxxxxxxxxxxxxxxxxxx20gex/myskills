# 矢量制作与验收

## 先建立结构清单

把事实整理成简短的表格或草图即可，不强制新增文件：

| 节点 | 输入 | 操作 | 输出 | 消费者 | 条件／证据 |
|---|---|---|---|---|---|
| 新增模块 | 真实张量来源 | 核心操作 | 张量或 logits | 实际融合点 | 代码函数、配置开关 |

同时列出符号表和两类改动：本次要修复的结构问题、本次要改善的版式问题。小幅翻译／字号修改无需重新推演全部模型。

## 选用确定性矢量工具

直接编辑 SVG、使用 Matplotlib 导出或复用项目现有矢量脚本都可以。优先复用现有实现，不为了统一框架重构绘图工程。

BDC 原项目的 `../assets/render_bdc_three_paths_editable.py`（相对 skill 文件夹）若存在，可作为案例起点；它不是本 skill 随附依赖。迁移后缺失时直接制作当前图，不搜索无关项目或假定脚本可运行。

Matplotlib 的几个关键设置：

```python
plt.rcParams.update({
    "font.family": "SimHei",  # 按当前环境的中文字体调整
    "svg.fonttype": "none", # 普通标签保留为 SVG <text>
    "pdf.fonttype": 42,     # 支持时在 PDF 中嵌入 TrueType 字体
})
```

SVG 引用了某字体，不等于嵌入了该字体。跨机器编辑时说明字体依赖；PNG／嵌入字体的 PDF 可用于固定展示。若出版社要求文字转曲，另存一份转曲文件，同时保留可编辑 SVG 原稿。

### 布局实现建议

- 用命名的节点位置和节点边界定义坐标。文字、箭头、图标都从节点坐标派生，避免改一个标签却忘记移动连线。
- 连线绑定节点端口或显式分叉点；终点留白只用于箭头尖端的视觉间隙，不允许产生悬空的语义输入。为残差保留独立侧通道，勿用框角或文字位置代替张量来源。
- 保留可复用的模块框、Token、矩阵、logits、端口和加号绘制函数；无需创建复杂通用图形引擎。
- 层级通常为：背景／分区 → 模块填充 → 连线 → 图标和端口 → 标签。检查背景是否盖住箭头；线段应停在节点边界，不能靠图层遮盖错误连接。
- 文字宽度变大时，调整换行或端点，不能让 `Patch Token` 等标签横跨原来留给短标签的箭头。
- 检查最终渲染的文字颜色：SVG 全局 `text { fill: ... }` 会覆盖元素的 `fill` 属性。需要逐对象配色时，统一由元素设置或明确的样式类控制，确保深色 Token 上的文字对比度有效。
- 先确定布局，再从同一版源文件导出所有格式。保留用户正在编辑的 SVG 改动；若渲染脚本会覆盖这些改动，先比较并合并，或另存新版本。

## 如果先用 GPT Image 探索

1. 根据用户指定模型和可用 skill 调用生成工具。提示词先描述画布／分区，再列节点、方向、输入、融合和精确标签。
2. 固定准确关系：两个独立编码器、并行辅助分支、残差汇合点、阶段条件。不要只说“照参考图画一个”。
3. 生成后核查结构，而非只看配色。颜色或文本很好看，不代表线条和数学含义正确。
4. 对明显的局部修订可以尝试一次精确编辑；连续两轮仍有同类乱码或连线失真时，优先转矢量重绘。用户要求逐处改字或持续编辑时，可直接转矢量。
5. 确认网络失败未产生成品后才考虑重试；没有新信息时不要无限重发收费请求。默认连续两次传输失败后报告限制，并完成可独立进行的矢量制作。

位图可作为视觉底稿。重绘最终 SVG 时，用路径、矩形、文本、箭头等真实图元重建；自动描摹轮廓不会自动恢复文字语义与正确拓扑。只有用户明确需要可追溯的底图标注稿时，才保留嵌入位图并说明其性质。

## 验收：结构、排版、格式分开检查

### 结构

- 对照节点／边清单确认每个消费者收到正确特征。无悬空的语义输入、无文本特征误入纯视觉分类支路。
- 共享参数、复用特征、复制显示分别表达；不要只写一个含混的 `Shared Encoder`。
- 协方差压缩、分类头、语义融合等真实步骤没有因加图标而被省略或挪到模块之外。
- logits 残差、概率融合和损失相加分别标清。总图只展示必要层次。
- 阶段文字和当前配置一致。基线已被更改的子模块不能标为“完全不变”。
- 按 [模型结构核对](model-checks.md) 沿每条边追踪，重点检查子层末端、残差起点、重复范围及注意力来源；结构检查与下面的格式检查分别给出结论。

### 排版

- 看完整 PNG，再放大新增区域、公式、密集图标、端口和箭头拐点。
- 标签不越框、箭头不穿字、矩阵不挡节点；合并处有清晰箭头方向。
- 无乱码、问号碎片、异常 Unicode、截断的框边或擦除补丁。
- 同名端口完全一致。逐一检查端口定义、每个使用点、尺寸公式与图例，防止只改一部分。
- 自动测文字包围盒只能检查部分溢出，不能替代视觉检查连线遮挡或语义错误。
- 在最终使用宽度检查最小标注与线宽，再放大检查端口；全图缩略预览用于判断重心、空白和主路径是否易于追踪。

### 格式

- 解析 SVG 检查 `<text>` 保留文字并核查 `<image>` 的用途。纯矢量示意图不应意外含位图；真实输入图片、对应 Patch 裁片可以保留位图，交付时说明。模块、连线和标签仍应为可编辑图元，不将整页 PNG 包装成 SVG。
- 文本对象数量仅用来诊断“是否全被转曲”，不作为固定质量指标，不锁定 95／96 等案例数值。
- 检查导出的实际像素尺寸，不能将请求分辨率当成实际 PNG 分辨率。
- SVG、PNG、PDF 同步生成。PDF 矢量版不等于每个编辑器都能逐项编辑，SVG 是主要编辑源。
- PDF 单独检查页数、页面尺寸并逐页渲染；浏览器打印需设置与画布比例一致的 `@page`、页边距和内容尺寸，不能依赖默认 Letter/A4 纸张。PDF 无裁切不代表源图结构正确。

### 可自动检查的边界

已有绘图环境支持时，用文本实际包围盒检查容器溢出，用命名端口检查边端点是否连接，用画布包围盒检查越界。检查器需要理解 transform、字体和绘图模型；未支持的特性报告“未检查”，不能用简单坐标正则承诺任意 SVG 都无重叠。结构语义仍须对照证据人工核查。优先复用环境中的检查能力，只有反复出现的确定性问题才新增专用脚本，不为一次绘图创建通用布局引擎。

## 交付方式

通常提供 SVG、PNG、PDF 三个链接和一张 PNG 预览，简要说明修正的结构与语言规则。按需要给出渲染源文件链接。不要把“通过文件解析”说成“已经证明模型关系全部正确”。

用户仅要求制作／修图时，不据此修改训练代码、实验指标或重新运行实验。
