# 张量与表示可视化

用户要求“画出 Token 变化”“展示矩阵／张量变化”“表现 Patch 切块”时使用。将表示直接画成可编辑方块、矩阵网格或叠片；总图中只展开指定或理解模型所必需的接口，细节过密时移到对应模块的局部子图。

## 先确定图元含义

对每个展开明确：输入形状 → 操作 → 输出形状、各轴含义、方块代表的单位、颜色含义，以及操作是否改变内容／数量／排列。以代码或论文为证据；未知尺寸用符号，不虚构数值。

- 一枚 Token 方块代表完整向量；一张 `N × D` 特征矩阵的一行代表 Token，单元格代表一个特征分量。切换这两种粒度时用展开引导或标注，不能悄悄把同一种方块的含义换掉。
- 图像 Patch 是原图区域，Patch Token 是该区域经过嵌入后的向量；用不同边框、内部纹理或标签区分。文本 Token 不称为图像 Patch。
- 注意力网格的一个格子表示 Query 与 Key 位置之间的权重；它不是 Token，也不是特征分量。
- 三维张量标清三条轴；高维张量用带分组标签的矩阵组表达，如每个批样本有多个头，不靠叠片厚度暗示未知维度。省略批维时全图统一说明。
- 用少量方块加省略号表示长序列，真实数量以尺寸标签为准。示意网格无需逐格对应真实大小，但必须说明抽样／示意，不能暗示 Token 被删减。

## 变换与画法

| 操作 | 前后图形 | 保持与变化 |
|---|---|---|
| Patchify | 图像二维网格 → 分离图块 → 按顺序排成序列 | 标出空间坐标或编号，保持切块到序列的对应关系；重叠 Patch 画滑窗而非无重叠拼图 |
| Flatten + Projection | 每个 Patch 展平成条带 → 投影 → Token 方块序列 | 标 `P²C → D`，每个 Patch 仍对应一个 Token；卷积 Patch Embedding 可直接表示等价投影，不声称代码必有 Flatten |
| 特殊 Token 插入 | 原序列前后插入带标签的深色方块 | `N → N+1` 等长度变化与实际插入数一致；不能默认每个模型都有 CLS |
| Positional Encoding | 位置向量序列与 Token 序列逐位置汇入 Add | 相加通常不增加长度或通道数；位置编码机制以模型为准，RoPE 不画成输入端普通位置向量相加 |
| Selection / Pruning | 长序列 → 选中位置高亮 → 短序列 | 标 `N → K`，保留被选 Token 的编号／颜色；不能画成求平均 |
| Merge / Pooling | 若干 Token 分组后汇入较少方块 | 标聚合范围，输出来自多输入；区分特征维度与 Token 数的变化 |
| Linear Projection | D′ 不同时改变矩阵宽度；D′ = D 时保持形状，用算子和样式变化表示特征更新 | `N × D → N × D′`，Token 轴保持不变；同维投影也会改变表示，不能当成恒等映射或纯重排 |
| Reshape / Transpose | 相同编号／色块按新轴重新排列 | 前后元素总数一致；Transpose 显示轴置换，Reshape 不暗示任意置换 |
| Split Heads | 投影后矩阵沿特征轴分组 → 多张带头编号的矩阵 | 每个头仍有完整序列长度，不把多个头画成序列分段 |
| Concat | 两组方块／矩阵沿指定轴接合 | 标拼接轴，输出该轴长度为输入之和，其余轴兼容 |
| Add / Weighted Sum | 同形状表示逐位置汇入加号或加权节点 | 输出形状通常不变，颜色混合只表示来源；存在广播时标明轴 |
| 多尺度特征 | 不同空间分辨率的网格或张量块 | 分别标 `Hᵢ × Wᵢ × Cᵢ`，分辨率下降不自动意味着通道也下降 |

Self-attention 前后常为相同的 `N × D`：保留序列位置与数量，用边框／填充变化表示内容已更新，注明“上下文混合”。若需要解释混合，选一个输出 Token 展示多输入加权来源，避免全连接线淹没总图。

## 两个展开示例

### ViT：图像到 Token

对于无重叠、整除的正方形 Patch，省略批维：

`H × W × C → Patchify(P × P) → N × (P²C) → Linear Projection → N × D`

其中 `N=(H/P)(W/P)`。绘制图像网格、带对应编号的图块序列、投影后的 Token 方块；如模型确实使用 CLS，再变成 `(N+1) × D`。位置嵌入相加保持该形状。

例如 `224 × 224 × 3`、`P=16` 时有 196 个 Patch，每块展平长度 768；可只画若干代表块与省略号并标“196 个”。D 由模型确定，不能因为 Patch 展平长度是 768 就假定 D 必须等于 768。输入不能整除时，先核实 padding、裁剪或实际滑窗规则。

### Attention：Token 到权重矩阵再到 Token

省略批维和头索引，单头 cross-attention：

`Q: m × d_k` 与 `Kᵀ: d_k × n` → `Scores: m × n` → `Scale / Mask / Softmax` → `A: m × n`

`A: m × n` 与 `V: n × d_v` → `O: m × d_v`

Q/K/V 用特征矩阵，A 用独立图例的权重网格，标明行是 Query、列是 Key；Softmax 沿 Key 轴进行。Causal mask 仅在适用时绘制：行列均按时间升序时，禁止访问未来的格子位于主对角线上方。遮罩区域标为不可访问，不能在 Softmax 前把它简单表示成零分数。

多头可示意为 h 张矩阵：输出 `h × m × d_v` → `Concat Heads: m × (h d_v)` → `Output Projection: m × D`。该例针对常规多头注意力，GQA/MQA 等变体的 Q 头数和 KV 头数按实现标明。

## 配色与排版

- 颜色优先标来源、空间位置对应或分组，不在同一图中同时暗示数值大小。数值热力图有真实数据才给色标；无数据的色块标“权重示意”，不随机造出看似真实的模型解释。
- 方块排列和维度标签共同表达形状，不单靠大小变化。不同形状示意可以不按比例，注明示意并保持同图规则一致。
- 来源色按 Token 编号／来源绑定，不按当前绘制下标绑定；插入 CLS 后原有 Token 的来源色保持一致。表示内容更新的颜色变化需另作说明。同形状输入输出尽量使用同尺寸方块；局部图缩放不同则注明，不让大小差异暗示特征降维。
- Patch 裁片取自同一输入图的对应坐标；用示意图时注明。多个矩阵叠放时说明叠片表示 Q/K/V、不同头还是批样本，不能让一组未标注叠片同时承担这些含义。
- 总图保留关键接口表示；局部子图用同名张量或编号与主图关联，展开引导线不加计算箭头，避免让人误以为新增计算分支。
- 标签放在网格外，轴名固定方向；方块数量、字号和线宽以最终使用尺寸可辨为准，优先省略中间元素而非缩小文字。

## 验收

1. 逐个展开核对单位、轴、输入／输出形状及操作；Selection、Merge、Projection 与 Reshape 的视觉含义不能混用。
2. 核查元素数量或矩阵乘法关系，例如 Reshape 元素总数守恒、Concat 指定轴求和、Attention 输出长度来自 Q。
3. 检查编号和配色对应是否声称了实际不存在的一一映射；聚合后只保留来源分组，不冒充某个原始 Token。
4. 确认用户指定的变化确实出现了图形化前后对照，不只写了一行尺寸；未展示的内部维度在图注说明。
5. 复用矢量验收流程检查实际图元、文本、局部放大和缩小预览。以上形状示例用于语义核对，不代表任意自动绘图器都能验证模型正确性。
